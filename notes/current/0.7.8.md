# Zopilot 0.7.8 开发计划

最后更新：2026-07-26

## 目标

统一 Codex CLI 和 BYOK 模型的 Zopilot 工具能力。
两种后端应使用同一套工具，并得到一致的结果、状态和界面反馈。
Codex 自带的命令、文件修改和网页搜索等工具仍属于额外能力。

当前 Codex 通过 `app-server -> HTTP MCP` 调用工具，BYOK 通过
`Agents SDK Tool -> 私有 RPC` 调用工具，两条路径使用了两套协议。

## 当前问题

### 1. 工具和 MCP 重复实现

- MCP 使用 JSON Schema 定义 `paper_read`。
- BYOK 使用另一份 Zod Schema，并写死 `tool/paper_read`。
- 新增工具时需要修改两套代码，Schema、错误和结果容易不同。
- `tools/list` 和 `tools/call` 目前只支持 `paper_read`。
- MCP 协议和 HTTP 生命周期由项目手写。
- 当前实现没有完整遵守 MCP 2025-06-18。
- 现有结构不适合接入更多本地工具或开源 MCP Server。

### 2. Codex 工具的消息展示不完整

Codex 会调用命令、文件修改、网页搜索、图片查看和 MCP 工具。
这些调用已进入消息 trace，但都会显示成相同的通用工具块。

消息区还不能清楚区分：

- Codex、Zopilot 和第三方工具，以及读取、搜索、命令和文件修改；
- 文本、图片、diff、命令输出，以及只读、写入和批准状态；
- 普通参数和敏感参数。

大量输出也缺少折叠、截断和脱敏规则。

### 3. BYOK 多模态能力未完成

- 图片和 PDF 附件目前只作为本地路径写入 Prompt。
- 远程模型无法直接读取本地路径。
- 图片没有转换成 `input_image`。
- PDF 没有转换成 `input_file`。
- 不支持 PDF 的模型没有文本或页面图片降级方案。
- Zopilot 已能渲染论文页面，但 BYOK 没有 `view_image`。
- Codex 能读取页面图片，BYOK 只能看到图片路径。

### 4. 工具结果和能力描述太简单

- Tool trace 的参数和结果都是字符串。
- 图片、文件、资源链接和结构化数据无法统一传递。
- BYOK 会丢失 structured content 和 metadata。
- `paper_read` 的页码和引用定位没有稳定保留。
- `tools: true` 不能说明模型是否支持图片、PDF 或 function calling。
- MCP 启动失败时通常只写日志，用户看不到工具状态。

### 5. 权限、状态和性能不够稳健

- Codex 可能继承用户自己的工具和权限配置。
- Zopilot 没有明确设置只读、写入和批准策略。
- app-server 的交互请求目前会被统一拒绝。
- 修改 BYOK 配置后，backend 可能继续使用旧配置。
- 已删除的 profile 可能静默回退到当前 profile。
- Codex 与 BYOK 切换时，对话上下文可能不一致。
- 每次读取论文前都会读取完整 PDF 并计算哈希。
- 同一篇论文同时构建时没有锁和任务复用。
- 缓存目录会被直接删除后重建。
- 取消回复不会停止 PDF 任务，两种后端的工具超时也不同。

### 6. 缺少跨后端测试

当前单元测试、lint 和构建均已通过，但仍缺少：

- 真实 Codex CLI 与 MCP 联调测试；
- BYOK 完整工具循环测试；
- MCP 协议兼容测试；
- 两种后端的相同工具结果测试；
- 图片、PDF、超时、取消和并发测试；
- 第三方 MCP Server 接入测试。

## 设计原则

1. Zopilot 工具是跨后端标准，Codex 自有工具属于额外能力。
2. 工具定义、执行、权限和结果只能有一份来源。
3. MCP 只负责传输，不保存论文业务逻辑。
4. 图片和文件不能只用本地路径表示。
5. 所有工具都要标明来源、类型、风险和状态。
6. 第三方 MCP 工具默认不可信，必须经过限制。

## 目标结构

- **Tool Registry**：统一管理 Schema、来源、权限、超时、取消规则和执行器。
- **Content 与 Artifact**：统一 text、image、file、resource 和结构化数据。
- **Artifact Store**：用 `artifactId` 安全读取大文件和图片。
- **MCP Gateway**：使用官方 SDK，向两个后端提供相同工具并接入外部 Server。
- **Backend Adapter**：只负责后端事件转换，不再各自定义 `paper_read`。
- **消息区**：按搜索、图片、命令、文件修改等类型显示专用内容。
- 普通只读工具默认折叠，写入操作显示风险和批准状态。

`paper_read` 应移出 `integrations/mcp`，成为普通 Zopilot 工具。

## 完成标准

- Codex 和 BYOK 使用同一份 Zopilot 工具定义。
- 相同工具调用得到相同的结果和错误。
- BYOK 能读取图片附件、PDF 和论文页面图片。
- 消息区能清楚显示不同来源和类型的工具。
- 工具不可用和批准请求对用户可见。
- 新增工具时不需要分别修改 Codex 和 BYOK。
- 第三方 MCP 工具受到明确的权限和安全限制。
